(2) I avoided data races by giving each worker its own argument structure, counter, and instance array. Each worker opens its own read-only file handle and updates only its own results. The main thread uses pthread_join to ensure all workers have finished before accessing their results. It then merges the instance arrays in file order. Since the workers do not modify shared data, no mutex or shared global variables are needed.
(3) OpenMP makes thread management simpler. I use #pragma omp parallel for to divide the work among threads, and OpenMP waits for them to finish. With pthreads, I create threads using pthread_create, pass pointers to their arguments, and wait for them using pthread_join. OpenMP’s reduction(+:count) safely combines the match counts. For instances, each iteration stores its results in partial[i], which I merge in file order after the loop. Both versions keep each worker’s data separate to avoid races, but OpenMP handles the thread management automatically.
